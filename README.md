# RendiAR · Workshop MBA

Kit para aprender a organizar trabajo con ChatGPT Work y producir artifacts de una propuesta de producto.

**Product, Technology & Operations 4.0 · 120 minutos · práctica guiada · sin nota.**

RendiAR es un caso ficticio: un empleado revisa los datos de un gasto antes de presentarlo. Vamos a crear concepto y requisitos, process flow, service blueprint, wireframe anotado y un registro de revisión. No construiremos una aplicación funcional ni procesaremos gastos reales.

## Empezá acá

1. Descargá **Code → Download ZIP** y descomprimí tu copia.
2. Renombrá la carpeta como `RendiAR_Workshop` si querés seguir los mismos nombres del deck.
3. Seguí la [guía de inicio](00_guia/INICIO_RAPIDO.md).
4. Usá el [encargo inicial](02_trabajo/encargo_inicial.md) para comprobar las fuentes y la entrega de un archivo.
5. Continuá con los [prompts P1–P5](00_guia/PROMPTS.md).

No necesitás instalar Git para seguir este recorrido. La copia descargada no se sincroniza automáticamente con GitHub.

## Reglas y datos

Las reglas R1–R7 están en la [política sintética](01_fuentes/politica_gastos_v01.md) y el escenario está explicado en el [brief v02](01_fuentes/brief_rendiar_v02.md). La fuente tabular vigente es `01_fuentes/gastos_ficticios.xlsx`, con 75 operaciones identificadas de G01 a G75.

Los datos, comercios e identificaciones fiscales son ficticios. Algunos faltantes y valores inválidos son intencionales. No completarlos por suposición.

La carpeta de tickets contiene 75 imágenes: G06 está ausente de manera intencional y G07 tiene una copia duplicada. También existen casos de alcohol, diferencias de total y fecha. Con estas fuentes pueden trabajarse R1–R7, siempre citando la evidencia y manteniendo la decisión humana.

La hipótesis de valor todavía no está validada. Revisar artifacts no demuestra que una aplicación funcione ni sustituye pruebas con usuarios.

## Comprobar y continuar

Después de cada entrega: abrir el resultado, contrastarlo con los casos, registrar hallazgos y decidir el cambio. Una persona acepta la versión; el nombre «final» o la carpeta donde se guarda no acreditan aceptación.

Actualizá `ESTADO.md` con rutas reales, versiones y el siguiente paso. Para tu propio proyecto, adaptá fuentes, reglas y criterios de aceptación.
